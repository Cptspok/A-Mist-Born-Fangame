Milestone 029 - Combat Rewards + Intelligence v0.1 + Parametric Ladders
Implementation date: 2026-09-18. Owner gameplay testing is pending.

1. DATA AND OWNERSHIP
CourtTargetDefinition: unique ID, name/unknown name, optional portrait/unknown portrait,
dossier text, district/region IDs, normalized marker position, location name, clue IDs.
IntelligenceClueDefinition: unique ID, target Resource, identity/location/tactical reveal
category, document text, reveal text, source and optional icon. All clues are unique.
IntelligenceMapDefinition and IntelligenceRegionDefinition: district ID/name, region
ID/name, normalized bounds and initially-known flag. IntelligenceCatalog lists maps
and available targets. These definitions remain immutable at runtime.
IntelligenceKnowledge is owned by RespawnSession. It records clue IDs, discovered
targets, category reveals and defeat history, with clue_discovered, target_discovered,
target_updated and cleared signals. New run/restart clears knowledge; checkpoint retry
retains it. No disk persistence, XP, kill progression or campaign gates were added.
A repeated target defeat after checkpoint respawn is possible, consistent with existing
world replacement; dossier defeat status explicitly means 'Defeated this session'.

3. REWARDS / EXISTING PICKUPS
EnemyController exposes rewards: EnemyRewardDefinition, with Items and Intelligence
Clues arrays. Items are ordinary ItemDefinitions, including existing consumable vials.
Each entry drops one item; repeated item entries author additional quantities.
Only designated carriers receive clue definitions. The death path issues rewards once,
defers spawning outside physics callbacks, and creates existing WorldItem pickups as
siblings of the corpse so fading the enemy does not remove them.
Clues are wrapped in new runtime document ItemDefinitions, never by mutating authored
resources. WorldItem -> InventoryComponent.try_add remains the pickup transaction.
Documents are read straight into knowledge, not stored as grid stacks. Full inventory
therefore does not block intelligence. Ordinary items retain inventory capacity rules.
Knowledge keys by unique clue ID; repeated array entries are filtered on drop, known
clues are not dropped on checkpoint retries, and duplicate world documents are consumed
without another discovery signal or stack. Item_added fires only on a new discovery.
No clue IDs appear in enemy scripts.

4. INVENTORY / INTELLIGENCE UI

visible; tab switching cancels item drags and context menus. Existing inventory/equipment
controls and pause/mouse ownership remain in place. IntelligenceView reads catalog and
knowledge, with an extensible target selector, map left and dossier right.
Unknown identity, portrait/dossier, location and tactical fields show ???. Identity

  Add it to one carrier's EnemyRewardDefinition Intelligence Clues array. Place normal

- Create IntelligenceMapDefinition with a unique district ID; create region subresources

- Different reveal categories can be added to the clue's string enum; knowledge already
  stores arbitrary categories and the document list renders their text. Specialized new
  category UI would need its own presentation, not a knowledge rewrite.

6. PARAMETRIC LADDER
world/interactables/parametric_ladder/parametric_ladder.tscn / world/interactables/parametric_ladder/parametric_ladder.gd (@tool).
Inspector: Height (1..40), Width, Rung Spacing, Rung Thickness, Climb Speed,
Front Offset and Top Exit Distance. Height/geometry changes regenerate two solid rails,
evenly distributed rungs and a tall interaction volume. Generated children are transient,
not serialized duplicates. Rungs are visual; rails have collision.
Placement: origin is bottom floor, local +Z is climbing face and -Z top landing. Keep
upright at unit scale, rotate around Y, resize through Height. Place the top at the
landing floor height and leave capsule clearance above it and along the exit path.
Use F (Interact) while standing near the face or top landing; W/S climb up/down.
Jump or Interact releases the grip. Reaching the top moves over the landing; descending
to the bottom releases normally. Top entry moves out to the face before descending.
The player motor owns collision motion and still emits external-motion/movement signals;
forces or impulses release the grip and retain their normal integration. No teleports.
Primary/secondary combat and combat ability inputs are blocked while attached; mounting
cancels held actions. No stamina, sliding, ladder animations or ladder combat added.
Narrow passages need space for the normal player capsule; blocked exits remain blocked
by geometry and can be abandoned with Interact/Jump. No ladder was placed in any level.
